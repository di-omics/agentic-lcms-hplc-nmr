Agentic LC-MS, HPLC and NMR: one round in simulation

A planning agent asks for measurements through 5 MCP tools. The gateway turns each request into the vendor's own unit of work, an Agilent Sample Scheduler XML command, a SCIEX OS batch or a Bruker SpinPilot experiment, and the vendor software keeps control of the instrument.

Every instrument and every number here is simulated. No instrument or vendor software was connected. The vendor call names and XML in the gateway's adapters (src/lab_gateway/adapters) are placeholders.

The round

Purity first, then plasma stability for the hits that pass, then NMR on the most stable one. 4 things go wrong on purpose: a swapped vial, 2 lost replies from SCIEX OS, and a drifted shim. The open bar is the time the LC-MS was held while nobody knew whether the batch had started.

When a reply is lost

Found. The first stability batch reached SCIEX OS and the reply did not come back. The gateway held the LC-MS, searched the SCIEX OS queue and history for the request id, found batch B0001, and kept monitoring. Nothing was submitted twice.

Not found. The TOPHIT-03 batch never reached SCIEX OS. After a 10 minute grace period the gateway stopped and asked for a person. A new LC-MS request was refused while the instrument was held. The operator checked SCIEX OS, recorded the decision under their name, and the gateway resubmitted.
